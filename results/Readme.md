# Results

This directory contains the numerical outputs generated by the evaluation notebooks for the experiments reported in the manuscript.

The study includes one **reference run (seed 42)** and two additional independent runs (**seeds 1 and 2**) used to assess sensitivity to patient partitioning and model initialization.

## Directory Structure

```text
results/
├── seed42/                     # Reference run
├── seed1/                      # Sensitivity run
├── seed2/                      # Sensitivity run
└── README.md
```

## Reference Run — Seed 42

The `seed42/` directory contains the results used for the primary analyses reported in the manuscript.

These outputs include, where applicable:

- validation threshold sweep results
- validation-selected operating threshold
- positive-test slice-level segmentation metrics
- positive-test summary statistics
- patient-clustered bootstrap results
- 95% confidence interval summaries
- lesion detection results
- training history and logs

The operating threshold was selected using the validation set only and was then frozen before evaluation of the held-out test set.

Patient-clustered bootstrap confidence intervals were computed using **2,000 bootstrap resamples**, sampling patients with replacement and retaining all positive test slices belonging to each sampled patient.

## Seed Sensitivity Analysis

The `seed1/` and `seed2/` directories contain corresponding results from the two additional independent experimental runs.

Together with the reference seed-42 experiment, these runs quantify variability associated with:

- patient-level train/validation/test partitioning
- model initialization
- stochastic training and balanced slice sampling

The preprocessing procedure and fixed 500-scan cohort were held constant across runs.

## Evaluation Design

All dataset partitions were constructed at the **patient level** to prevent slices from the same patient from appearing in more than one partition.

Primary segmentation performance is evaluated on nodule-positive slices from the held-out test partition.

For each experimental run:

1. The model was trained using its corresponding training partition.
2. The operating threshold was selected using only the validation partition.
3. The selected threshold was frozen.
4. The held-out test partition was evaluated once.

No test-set results were used for model selection or threshold optimization.

## Reproducibility

The files in this directory are generated by the notebooks located in:

```text
notebooks/
├── 02_UNet_Training.ipynb
├── 02B_Seed_Sensitivity_Training.ipynb
├── 03_UNet_Evaluation.ipynb
└── 03B_Seed_Sensitivity_Evaluation.ipynb
```

Cohort definitions and patient-level partition metadata are provided separately in the repository's `metadata/` and `splits/` directories.

The trained Keras model checkpoints are not stored in the repository because of their file size. They can be regenerated using the provided training notebooks and experimental metadata.
