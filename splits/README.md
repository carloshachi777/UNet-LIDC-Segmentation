# Patient-Level Data Splits

This directory contains the patient-level train/validation/test partition assignments used in the experiments reported in the manuscript.

All partitions were created at the **patient level**. No patient contributes scans or slices to more than one partition within an experimental run. This prevents information leakage between training, validation, and test sets.

## Experimental Design

The study uses a fixed cohort of **500 LIDC-IDRI scans originating from 498 unique patients**.

Three independent experimental runs were performed using random seeds:

- **42** — reference run used for the primary manuscript analyses
- **1** — sensitivity run
- **2** — sensitivity run

For each run, patients were randomly assigned to training, validation, and test partitions using the same predefined partitioning procedure.

The patient partition was re-drawn independently for each seed. The underlying 500-scan cohort and preprocessing procedure remained fixed.

## Reference Split — Seed 42

The reference experiment uses a patient-level split corresponding approximately to a **70/15/15 train/validation/test ratio**.

The resulting partition contains:

| Partition | Patients | Scans |
|---|---:|---:|
| Training | 349 | 350 |
| Validation | 75 | 76 |
| Test | 74 | 74 |
| **Total** | **498** | **500** |

Two patients in the cohort contribute two scans each; therefore, the number of scans exceeds the number of unique patients.

## Role of Each Partition

**Training set**

Used to estimate the U-Net model parameters.

**Validation set**

Used for model monitoring, early stopping, checkpoint selection, and selection of the segmentation operating threshold.

**Test set**

Held out from model development. The selected model checkpoint and validation-selected threshold were applied to the test set only after model-selection decisions had been completed.

## Seed Sensitivity Analysis

Seeds 1 and 2 define additional independent patient-level partitions used to assess the sensitivity of the results to data partitioning and stochastic model training.

These runs are **not cross-validation folds**. They represent three independent train/validation/test experiments.

The operating threshold was selected independently from the validation partition of each run and subsequently frozen before evaluation of that run's held-out test partition.

## Data Leakage Prevention

The following constraint is enforced for every experimental run:

```text
training patients ∩ validation patients = ∅
training patients ∩ test patients       = ∅
validation patients ∩ test patients     = ∅
```

Thus, slices originating from the same patient cannot appear in different partitions within a run.

The split files provided here allow the patient partitions used in the reported experiments to be inspected and reproduced.
